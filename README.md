# 淀粉粒考古图版库 · Starch Atlas

面向学术研究与教学的图版、文献及遗址信息展示网站。当前公开目录收录 628 幅图版；网页支持中英切换、遗址地图、图版与文献检索、分图释读和滚动致谢。

此仓库保存可部署的展示版本。日常编辑、审核和发布仍在维护者的本机后台完成。

## 目录

- `website/`：静态网页、公开元数据和预览图。
- `r2-worker/`：高清原图的只读服务代码。
- `待上传原图清单.json`：628 幅原图的对象键、大小与 SHA-256。
- `scripts/check-release.mjs`：静态资源、公开文件及图片地址检查。

高清原图约 2.77 GB，使用独立对象存储。本仓库不保存原始 PDF、高清原图、编辑数据库、模型或本机维护历史。

首版按维护者要求不公开 CSV 下载表。内部审核清单与作者候选核对资料保留在本地，未列入此仓库。

## Cloudflare Pages 部署

1. 在 Cloudflare Pages 中选择 **Connect to Git**，连接本仓库。
2. 生产分支使用 `main`，框架预设选择 `None`。
3. 根目录保持仓库根目录；构建输出目录填写 `website`。
4. 正式部署的构建命令填写 `node scripts/check-release.mjs`。
5. 按下节配置图片服务地址，再发布。

Git 集成后，推送 `main` 会触发网页更新。功能修改可先使用分支预览，确认后再合入 `main`。

## 高清图片配置

当前 `website/config.js` 的 `mediaBaseUrl` 尚为空，因此这还是上线准备版本，高清图服务尚未接通。

1. 创建 R2 Standard 桶，将原图上传为清单中的 `media/<图版ID>.png` 对象键。
2. 按 `r2-worker/wrangler.jsonc` 配置 `IMAGES` 绑定并部署只读 Worker，或使用绑定自有域名的 R2 图片服务。
3. 在 `website/config.js` 将 `mediaBaseUrl` 设置为实际 HTTPS 根地址，例如 `https://images.example.org`，末尾不带 `/media`。
4. `apiBaseUrl` 保持为空；`catalogUrl` 保持 `data/catalog.json`。
5. 检查若干原图的读取、下载和 SHA-256，再向读者开放正式地址。

检查准备包可执行 `node scripts/check-release.mjs --draft`；正式检查会要求填好真实图片服务地址。

## 更新维护

在本机后台完成修改、核对和发布后，重新导出当前展示文件，将新的 `website/` 同步至仓库。更换了原图时，同时更新对应的 R2 对象；仅修改文字或界面时，更新网页即可。不要将整个工作目录提交到本仓库。

网站正式发布、手机与电脑验收通过后，再为长期稳定网址制作书稿二维码。
